# QQ 音乐歌词

Android 与桌面共用 QQ 歌词客户端、QRC 解析器和现有歌词渲染模型。无需额外服务或 QQ 音源插件。

## 来源选择

启用的网易、AMLL、QQ 三源同时启动，每 250 毫秒按最新结果择优更新，最多每秒四次，不要求网易先显示，也不等待其他来源到齐。一个周期内的中间结果可以跳过，但最后一批结果一定会在下一个周期处理。已有结果不会被空结果、错误或低优先级结果覆盖。

保留 AMLL 逐字、网易逐字、QQ 逐字、AMLL 行级、网易行级、QQ 行级的选择顺序。QQ 即使在网易有逐字时也并行查询。QQ 八秒超时；AMLL 单次镜像请求和总等待均为六秒。网易与已启用的 QQ 均结束且无可用歌词（包括失败或超时）时，提前取消尚未结束的 AMLL；已经取得的 AMLL 歌词保留。QQ 关闭时不触发此提前取消规则。关闭的来源不发起查询，切歌会取消所有未结束查询。全部来源结束仍无可用歌词时才输出空结果或回退本地。QQ 歌词源默认启用，可在歌词设置中通过“启用QQ音乐歌词源”（位于 AMLL 开关上方）独立关闭；开关持久保存，并触发当前歌曲重新选择歌词。关闭 QQ 后不读取其缓存、不请求网络。关闭 AMLL 不会关闭 QQ。

现阶段自动匹配只用于正数网易歌曲 ID（含已关联网易的本地歌曲）。未关联网易的本地音频、外部平台负数 ID 和播客不主动搜索 QQ。QQ 不需要登录；接口限制或风控时自动回退。下载的歌词旁文件仍沿用下载器原来的网易接口。

## 匹配

参考 Mei 的歌名清理与五秒时长门槛；每次只评估搜索前五项，并复用 Melodia 的 `SongMatcher` 校验歌名、歌手及专辑评分。缺少歌手、时长或 QQ 数字 ID 不自动采信。搜索依次使用原歌名加首位歌手、去括号歌名加首位歌手、原歌名。Lite 搜索返回权限错误或空结果时改用公开搜索接口，并保留数字 `songid`（而非播放用的 `songmid`）。保留原歌名参与候选校验，避免清理版本标签后直接接受不同版本。

仅成功解析的结果保存到进程内缓存，最多 32 首、30 分钟；失败不缓存，不写入永久歌曲映射。QQ HTTP 客户端不携带网易鉴权或 Cookie，切歌取消会传递到底层请求。

## 格式

十六进制数据经三密钥 DES 和 zlib 解压后，支持 XML `LyricContent`、纯 QRC、普通 LRC。逐字时间统一转换为相对行起点的偏移；整行使用同一绝对/相对时间判断。翻译与罗马音按三秒内最近起点一对一合并，过滤版权声明与占位内容。不识别背景人声或对唱，不生成角色或背景行。
