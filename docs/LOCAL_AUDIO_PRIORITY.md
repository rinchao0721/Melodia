# 优先使用已有本地音频

适用版本：Melodia Personal `2.0.0-beta.12`。

本功能适用于手机上已有的普通、可解码 MP3、FLAC、WAV 等文件。它保存文件引用，不会复制、移动、修改或删除原音频，也不会把外部文件写入 Melodia 的下载记录。

## 一键批量匹配并查看结果

扫描或导入音频后，在设置 → 本地与网易云匹配 → 歌曲批量匹配与待处理进入管理页；本地音乐设置和播放与下载设置也有同一入口。本地音乐首页已恢复原来的主要布局，不再展示匹配卡片。每次开始自动匹配都会重新处理未命中、需确认和出错项，并复用旧候选按当前规则检查；已匹配或已有关联的条目跳过。每轮处理一次后停止，不反复循环。每首检索最多前 100 个候选，核对歌名、歌手、专辑与时长后自动保存符合规则的结果；原有手动关联和已解除的自动匹配限制不会被替换。

结果页面的主按钮始终用于自动处理：未开始时显示“开始自动匹配”，已有处理记录时显示“继续自动匹配”，运行中显示“暂停自动匹配”。有待处理歌曲时可重新开始或继续，不会因已有报告而改成只能人工处理。旁边独立的“人工核验 · 连续处理”用于逐首核对；它会先暂停自动任务，再打开候选，不创建一轮新的自动搜索。

页面显示逐首进度，可筛选全部、已匹配、未命中、需确认、出错和待处理，查看本地及在线专辑缩略图、歌曲信息和原因。缺少封面时异步补取，失败保留占位图。需确认的项可直接点候选关联，单候选可点击“选用并关联”，没有二次确认。成功后保持当前筛选并定位下一条未处理歌曲，取消或失败保留当前位置；仍可修改关键词继续搜索。按钮区可以换行，字体放大时自动入口仍单独可见。

任务可暂停、继续，关闭结果页仍会在当前应用进程内处理；进程被系统结束后保留已完成结果，下次点击继续。网络失败或接口受限会记为“出错”并暂停，剩余歌曲继续保持待处理，不算“未命中”。不需要另点击“重试未匹配”。

仅搜索和核对时忽略明显曲目序号，例如 `01 五味瓶`、`01. 五味瓶`、`01 - 五味瓶`、全角数字；保留 `1989`、`505`、`7 rings`、时间和小数等真实数字标题。已知歌手出现在标题前后时，可识别 `歌手 - 歌名` 和 `歌名 - 歌手`；缺歌手标签时只从规范的文件名格式提取。文件名、标签和曲库显示原名不变。若真实在线歌曲的完整标题确实带数字，优先采用完整标题相同的候选。

本地歌手可为在线歌手集合的非空子集，例如本地只保留主唱、在线还列出合作歌手。专辑核对忽略明确的重制/重铸、Japan/US/EU 等发行版本后缀，保留专辑主体。多个发行 ID 均符合规则时，优先完整歌名、原专辑名、完整歌手、最接近时长和原发行版本，再按 ID 稳定排序；这是检索结果范围内的选择。同一歌曲的其他编码若已有可读优先音源，报告显示“已有优先音源”，保留当前音源，不重复建立或替换关联。

## 专辑批量自动对应与人工完成（beta.12）

在“设置 → 本地与网易云匹配 → 专辑批量匹配与核验”点击“开始批量匹配”，逐张搜索对应的网易云专辑并核对完整曲目。可按全部、已完成、待核验、未处理、未命中、出错六类查看，也可用专辑名或歌手筛选。每轮对未完成专辑处理一次；再次继续会跳过已完成项，重新处理其余项。未知专辑不作为可自动对应的正常专辑。

“已完成”表示这张专辑已经无需自动重试，满足以下任一条件即可：歌曲全部已有对应，或用户已成功完成人工确认。点开待核验专辑、选中候选查看预览，都不会直接确认。检查对应关系后点击“确认专辑并匹配 N 首”；没有可自动项时，点击“确认专辑并完成核验”。即使此前已保存过专辑对应，仍可完成这次人工核验。专辑页中手动点选歌曲候选并保存成功，也会记录对当前专辑的人工确认，无需再重复点击确认。

**专辑核验完成与歌曲全部关联分别记录。**例如一张专辑人工核验通过、只有 8/12 首已保存关联，可以显示“已完成”，同时继续显示“歌曲 8/12 已关联”。剩余歌曲不会被虚构为已匹配；从已完成列表再次打开专辑，仍可单独处理它们。批量操作会跳过已人工确认的专辑，避免反复把它放回待核验。

人工确认只对当时的本地专辑内容及所选网易云专辑有效。新增或移除曲目、修改标签/时长/文件大小/路径等会使旧确认失效；原有歌曲关联继续保留，列表重新依据当前歌曲关联数和报告确定状态。仅扫描时间或关联歌曲 ID 更新不会使确认失效。更换到另一张在线专辑要重新确认；只查看其他候选然后取消，原来已保存的对应关系保留。“解除专辑对应”会同时清除专辑层的人工确认，但不解除歌曲关联；如果所有歌曲仍已关联，专辑仍可因歌曲全覆盖显示已完成。

暂停、取消、自动歌曲写入失败或确认过程中本地内容变化时，不新增人工完成标记。已经保存成功的歌曲引用保留。确认记录跨重启保留；旧版缓存没有可靠的人工核验标志，因此升级后不会把旧的部分关联专辑直接推定为人工完成，只需确认一次。

自动选择专辑要求专辑名、歌手及录音类型相符，且歌名和时长可确认至少 80% 的本地独立曲目；本地有至少 3 首独立曲目时，至少确认 3 首，只有 1–2 首时需全部确认。重复编码在判断专辑时合并计数，不能增加证据数量。对能够确认属于同一录音的多个发行版本，按曲目覆盖、时长接近程度和原版优先选择；不同歌手归属、Live/Remix/重录等差异或曲目不完整仍进入待核验。这个过程不会仅按曲目数量或顺序配对。

专辑确定后，歌曲沿用下方的专辑内宽松规则，保存前重新读取当前音频，保留已有歌曲关联、其他优先音源和已解除的自动匹配限制。有专辑对应、歌曲仅完成一部分且尚未人工确认时，自动续写前先重新获取完整在线曲目，不能将旧缓存默认视为完整。自动批量保存对可以确认同一录音、时长彼此相差不超过 2 秒的重复编码择优保存一个音源；不能确认等价时留待核验。已有优先音源不因批量处理而被替换。

可随时暂停；搜索会取消，已开始的当前保存完成后停止。关闭页面也会请求暂停，已完成专辑报告及关联跨重启保存，下次点击继续处理剩余项。网络或服务限制会作为出错记录并暂停，不当作未命中。点开报告中的专辑会先停下批量任务，并直接显示已保存候选或对应关系，避免重复搜索；需要时仍可修改关键词。歌曲备份 JSON 不包含专辑对应关系、人工核验标记、完整专辑曲目缓存或专辑批量报告。

## 双向专辑对应与专辑内匹配（beta.10）

设置 → 本地与网易云匹配提供“本地专辑”和“网易云专辑”两个起点。可以先选本地专辑、搜索并选定网易云专辑，也可以先搜索网易云专辑，再从推荐或全部本地专辑中选择对应项。两边共用同一份对应关系。本地专辑详情的链接图标、网易云专辑详情更多菜单也有快捷入口。

先预览两张专辑和逐首匹配结果，点击“确认专辑并匹配”才保存对应关系并处理可自动项；也可手动点选专辑内候选。确认后仅在所选网易云专辑曲目列表中匹配，忽略本地歌手署名与专辑标签差异，并清理序号、歌手前后缀、标点和明确的重制/地区发行注释。唯一同名且时长差在 5%（最少 5 秒、最多 15 秒）以内时可自动关联。缺少时长、多同名、多个本地文件争用同一在线歌曲、Live/Remix/伴奏等录音差异仍需核对；曲号仅用于推荐排序，不能单靠顺序自动关联。

自动项写入前重新读取音频并按完整专辑曲目重核，保留已有手动关联、其他优先音源及被解除的自动匹配限制。待确认项可在同一页展开候选或查看这张专辑全部曲目，点选直接保存，列表不跳回顶部。暂停在当前歌曲处理完成后生效，已完成结果保留。专辑对应和在线曲目缓存独立保存，重启后可直接继续；“解除专辑对应”只清除专辑层对应，不解除歌曲关联。现有歌曲关联导入导出仍适用，专辑层对应目前不包含在歌曲备份 JSON 中。

## 自动使用本地曲库

1. 在应用的本地音乐中扫描音乐目录，或通过文件/文件夹导入已有音频；
2. 设置的播放与下载页面中，“优先使用本地音频”和“自动匹配本地曲库”默认开启。
3. 从在线搜索或歌单播放歌曲时，播放器根据完整歌名、歌手、时长与专辑核对本地曲库。默认时长差不超过 2 秒；同一专辑可容许时长的 2%，限制在 2–5 秒之间，以容纳结尾静音等差异。
4. 自动匹配首次需要联网取得在线歌曲的完整元数据。元数据确认并缓存后，下次可以离线匹配；第一次就离线且尚无元数据时，请使用手动关联。

只有在线确认为多人演唱且专辑相同时，才将本地 `歌手A/歌手B` 拆成多个歌手；`AC/DC` 等单个歌手名不会随意拆分。

同一物理文件被扫描和导入两次，只算一个候选。如果多个文件均为同一歌名、兼容歌手与专辑，时长彼此不超过 2 秒，优先选择 FLAC/APE 等格式。Live、现场、重录、伴奏、Remix、不插电等不同录音版本仍分别核对，并检查只出现在文件名里的版本提示；歌手别名、缺标签及无法确认的版本需手动关联。

播放时的自动匹配不会批量保存关联；设置中的批量匹配会保存已确认结果，两者可分别使用。本地列表没有“已关联网易云”标记，不代表在线播放无法自动使用它。

## 从本地歌曲关联网易云

设置 → 本地与网易云匹配 → 歌曲批量匹配与待处理打开固定全屏报告，待处理包含未开始、未命中、需确认和出错。六个分类全部显示，不需要横滑查找。

点击“人工核验 · 连续处理”或任意待处理歌曲，在同一页面核对缓存候选；点选直接保存并进入下一首。“稍后处理 · 下一首”跳到下一首，不改其状态；返回报告保留原分类和列表位置，不反复关闭和重新打开弹层。进入人工处理时暂停自动匹配，避免后台保存竞争。搜索栏在需要其他候选时展开，封面加载不阻塞选择，也不重置候选列表位置。

每次人工确认只更新相关报告条目，不重新读取并写入整个曲库。音频只解析一次，物理别名核对仍读取当前文件身份以防误关联。关联已保存而报告更新失败时，会明确提示刷新报告，已成功的关联不会撤销。返回报告后，使用主按钮“开始自动匹配”或“继续自动匹配”处理剩余项，已成功关联仍跳过。

手机新加入音频后，点击报告中的“刷新曲库”：先等待自动匹配暂停，再扫描系统 MediaStore，将结果同步到本地曲库后更新报告。刷新完成后新曲目进入未开始状态，可点击“继续自动匹配”。刷新期间开始匹配和人工核验暂不可用；出错时保留已有记录并恢复操作。此操作需要已授予本地音乐读取权限，缺权限时会提示先到本地音乐页面授权；不会自动弹出授权或取得新的文件夹访问权。仅已被系统 MediaStore 收录的音频会通过扫描新增，其他文件仍需从本地音乐导入。打开报告、关联后更新状态等普通刷新只读取现有曲库，不反复扫描手机。

进入本地音乐 → 全部歌曲（或本地歌单）→ 歌曲的“更多” → “关联网易云歌曲”。搜索框预填歌名和歌手；结果展示歌手、专辑与时长。同专辑、同标题和时长接近的结果靠前，但不自动替你确认。

点选正确歌曲与版本即保存关联。本地列表显示“已关联网易云”，菜单可更换或解除关联。播放仍使用原本地文件；关联也让对应的在线歌曲优先找到该文件。显式选择其他文件会更换该在线歌曲的优先来源。

## 从在线歌曲关联本地文件

在在线歌曲的“更多操作”中选择“关联本地音频（优先播放）”，首先打开已扫描/导入的本地曲库。搜索、歌单、专辑、歌手和全屏播放器的歌曲菜单均有入口，打开菜单及关联不需要登录。喜欢、收藏等账号操作仍按原规则要求登录。

beta.9 默认显示根据歌名、歌手、专辑和时长排列的推荐，标出相同歌名、歌手、专辑、时长接近或版本差异等依据；可直接切换“同歌手”“同专辑”“全部”，查看本地封面、原始标签和文件名后点选关联。输入搜索时默认在全部曲目中搜索歌名、歌手、专辑和文件名，也可再按分类缩小范围。序号与歌手前后缀清理、合作歌手精简、专辑地区/重制注释沿用原匹配规则，Live 等录音版本差异保留提示。推荐不会自动写入关联。

列表只读取现有曲库元数据，不联网搜索或逐个打开音频。点选时才核查文件可读性和授权，失败保留当前页面重试。尚未导入曲库的音频仍可用页面底部“从文件选择未导入的音频”；取消文件选择返回原列表位置。Melodia 自己的已下载歌曲已有本地播放路径，不列为额外外部关联候选。被本地音乐扫描设置排除的条目与本地曲目页保持一致。

关联会跨应用重启保留；下一次播放这首在线歌曲时优先使用关联文件。可以更换或解除关联。解除关联会同时停用这首歌的自动匹配，避免马上重新选回同一文件；原音频保留。需要时在菜单中选择“恢复本曲自动匹配”。

手动选择优先于自动匹配。手动文件失效时直接回退原有下载、缓存或在线流程，不静默换成另一个本地版本。全部来源均不可用时继续沿用原来的错误/离线处理。

beta.12 将系统文件选择器和本地曲库选择的保存路径统一。显式把同一物理文件改关联到另一首在线歌曲时，会替换它原来的对应，并停用被替换歌曲的自动匹配，避免马上把同一文件匹配回去。保存前和实际写入时核对文件身份；歌曲关联、快照及自动匹配排除记录一起写入。

如果自动解析本地音源期间你更换了手动文件、解除关联或关闭开关，返回播放地址前会重新检查当前选择。新手动选择优先；新文件不可读时按原播放流程回退。此次检查复用已取得的自动候选，不为处理竞争状态再发起一轮自动搜索。

## 关联导出与导入

入口：本地音乐 → 右上角“更多” → “本地音乐设置” → 本地音频关联。也可在设置 → 播放与下载中使用。

- **导出已确认的本地关联**：通过系统文件选择器保存 JSON，包含手动或批量确认的网易云歌曲 ID、文件引用和核对信息。备份不包含音频，也不包含播放时临时计算的自动匹配结果。旧版关联或暂时不可读的条目仍保留，并提示问题。
- **导入本地关联**：先扫描或导入当前手机上的对应音频，再选择 JSON。预览区分可新增、已存在、冲突、待重选；点击确认才写入可新增项。冲突保留现有关联，无法确认的项跳过。

换机后的 MediaStore/SAF 地址可能改变；恢复使用当前已授权曲库的文件名、标签、专辑、时长和文件大小核对，不把旧地址当作跨设备身份。两份不同物理文件都满足证据时要求重新选择。相同歌曲换了编码或文件被改写后，也可能需要重新手动关联。JSON 不替你授予音频访问权限，不覆盖现有关联，也不改变本地优先开关。

## 优先级与设置

播放队列明确指定的本地文件 → 可读取的手动关联/唯一自动匹配文件 → Melodia 有效下载记录 → 原来的缓存/在线流程。

关闭“优先使用本地音频”后，在线歌曲不再使用这些外部关联与自动匹配；已有本地音乐入口仍可直接播放文件。关闭自动匹配只影响自动选择，手动关联仍可使用。切换文件授权、移动文件或删除文件后，可重新关联，或让播放器回退其他来源。

## 旧数据和异常报告恢复

beta.12 沿用原有歌曲关联、独立批量报告数据库和专辑对应存储，不修改官方 Room 数据库或下载表。专辑确认字段是有默认值的可选字段；旧记录可读取，未知字段可忽略。确认字段损坏时仅失去人工完成标志，仍保留可读取的专辑和曲目缓存。

歌曲报告逐条解码：一条 JSON 损坏或记录 URI 不一致，不会阻止其余报告加载。刷新曲库时，依据当前曲库和实际已确认引用重建受影响条目，并显示恢复提示。候选和旧报告状态无法恢复时会回到需要处理的状态；这不等同于已经保存的播放引用丢失。数据库文件本身无法打开、音频丢失或授权失效仍需针对原因处理。

暂停入口共用一个流程：取消并等待当前自动任务结束，核对最后一条实际保存结果，再释放暂停状态。保存暂停进度出错时会提示，仍释放状态，避免“已暂停”之后无法再次开始。

## 代码和后续维护边界

- `domain` 的匹配和完成策略负责纯规则；`data` 负责文件核验、在线查询及独立存储；`ui` 负责列表、筛选和操作状态。推荐候选与写入歌曲引用分开。
- `AlbumReviewPolicy` 计算专辑完成依据；`LocalAlbumMatchFingerprint` 为人工核验与批量报告共享内容指纹。确认使用条件写入，已被其他操作替换的专辑范围不能被旧页面标记为完成。
- 播放器和离线可播放索引经 `core.localmusic.LocalMusicApi` 查询可用音源和变化事件，由 `feature/localmusic` 实现接口。`core` 不直接依赖本地匹配 Repository 或其存储。
- 专辑缓存 JSON 解码在后台执行；单条核验不应触发主线程全库解析。歌曲备份格式与专辑报告格式保持独立，后续变更不能把一个状态当作另一个状态的事实来源。

这些边界用于缩小官方更新时的冲突范围。接入新官方版本后仍须验证播放源解析、本地文件身份、暂停恢复、旧数据读取和专辑人工完成；具体更新流程见 [个人构建与更新](PERSONAL_BUILD.md)。
