# 平板全屏播放器设计文档

日期：2026-09-25
状态：**已确认**
分支：`worktree-tablet-adaptation`
效果图：[布局方向](2026-09-24-tablet-fullscreen-player-mockup.html)、[卡片布局](2026-09-24-tablet-fullscreen-player-cards-mockup.html)（选定 B3）

## 1. 背景

平板 Expanded 断点下，播放器以常驻侧栏面板的形式和内容区并排。侧栏左上角已有「侧栏 / 全屏」切换按钮（`ViewSidebar` 图标，在下拉箭头左侧），点击后卡片左边缘向左铺满到距屏幕左边 8dp，退出方式为：切换按钮或返回键回到侧栏，下拉箭头或下拉手势收起到迷你条。

目前全屏态只是临时方案：背景铺满，内容仍是侧栏宽度的一列居中。本文档定义全屏态的正式布局。

## 2. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 布局方向（横屏） | 方案 B：左播放、右歌词 |
| 评论、艺人等卡片（横屏） | B3：右栏可整体滚动，第一屏是歌词，往下滑接两列卡片网格 |
| 卡片网格排布 | 按效果图：评论占满一行；下一行左「关于艺人」、右「歌曲信息」；「艺人专辑」「相似艺人」各占满一行；顺序与现在一致 |
| 竖屏 | 沿用手机全屏播放器的单列样式：封面与控件在上，往下滑依次出现卡片（B1 式下滑） |
| 歌词预览卡片、单行歌词 | 横屏全屏态都不显示（右栏已有完整歌词）；竖屏沿用手机样式照常显示 |
| 滚动冲突 | 按下点在某行歌词的文字范围内再拖动时滚动歌词，其余位置拖动滚动整栏 |
| 歌词手动滚动 | 不显示居中线与播放胶囊；点某一句即跳到该句播放 |
| 回到歌词 | 往回滑；另外滑离歌词区后右栏顶部浮出「回到歌词」小胶囊，点击平滑滚回顶部 |
| 无歌词（纯音乐 / 暂无歌词 / 加载失败） | 歌词区缩成一行提示，卡片直接上移到第一屏 |
| 侧栏 ⇄ 全屏过渡 | 铺开同时两套排版交叉淡入淡出（见 4.3） |

## 3. 布局规格

全屏卡片沿用双卡片风格：避开状态栏与手势条，四周 8dp，圆角 16dp，背景为封面取色的 `PlayerBackdrop`。顶栏（侧栏按钮、下拉箭头、播放来源、更多）位置与侧栏态一致，横跨整张卡片。

### 3.1 横屏（以 1280×800dp 为例，卡片约 1264×744dp）

```
┌──────────────────────────────────────────────────────────┐
│ ▣ ˅              播放自歌单 “Taylor Swift”             ⋮ │  顶栏
│                                                          │
│   ┌──────────┐    │  歌词行（暗）                         │
│   │          │    │  歌词行（暗）                         │
│   │  封面    │    │  当前行（亮、放大、带翻译）            │  右栏：可整体滚动
│   │          │    │  歌词行（暗）                         │  第一屏 = 歌词区
│   └──────────┘    │  歌词行（暗）                         │
│   歌名        ♡   │ ─ ─ ─ ─ ─ ─ ─ ─（往下滑）─ ─ ─ ─ ─   │
│   歌手            │  ┌ 评论（整行）────────────────────┐ │
│   ━━━━●──────     │  ├ 关于艺人 ─────┬ 歌曲信息 ───────┤ │
│   ⤮  ⏮  ⏯  ⏭  ⟳  │  ├ 艺人专辑（整行）────────────────┤ │
│   ▢          ⤴ ≡  │  └ 相似艺人（整行）────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

- **左栏**：固定宽度 420dp，距卡片左边 48dp，内容整体垂直居中，不滚动。自上而下：封面（边长取左栏宽度与可用高度中较小者，横屏约 340dp）、歌名歌手与收藏、进度条、播放控件、快捷操作行（输出设备、分享、播放队列）。单行歌词在全屏态去掉，右栏已有完整歌词。
- **右栏**：左栏右侧 56dp 起，到卡片右边 40dp 止（约 700dp 宽）。
  - 歌词区：高度等于右栏可视高度，复用 `FullScreenLyricsList`，字号沿用用户在歌词设置里选的大小。
  - 卡片区：两列网格，列间距与行间距 12dp，底部留 24dp。
- 「回到歌词」胶囊：歌词区完全滑出后出现，位于右栏顶部居中、顶栏下方 8dp，淡入淡出。

### 3.2 竖屏（以 800×1280dp 为例，卡片约 784×1224dp）

沿用手机全屏播放器的单列排版（封面、歌名歌手、单行歌词、进度条、控件、快捷操作，往下滑是歌词预览与各信息卡片），内容列占卡片宽度的 62% 并居中（参照 Spotify 平板竖屏全屏，800dp 宽平板约 486dp）。封面仍按可用高度收缩，保证首屏完整显示到快捷操作行。

### 3.3 无歌词（横屏）

歌词区高度收成一行（约 56dp），居中显示「纯音乐，请欣赏」或「暂无歌词」，卡片紧接其下。歌词加载中仍显示现有的加载态，占满歌词区高度，加载完再按有无歌词决定高度。

## 4. 交互

### 4.1 手势分流（横屏右栏）

- 按下点落在某一行歌词的**文字范围**内（不是整行宽度）再拖动：滚动歌词。不显示居中线与播放胶囊，松手后停留片刻自动回到当前行。
- 按下点落在歌词区空白处、卡片区等其他任何地方：整栏滚动。
- 单击某一行歌词：跳到该句播放（沿用现有 `onLyricClick`）。
- 歌词区在屏幕上可见时，自动滚动照常进行；整栏滑到卡片区后，歌词区停止自动滚动，滑回来时直接定位到当前行。

### 4.2 卡片

卡片点击行为全部沿用侧栏 / 手机端：评论卡打开评论弹层；艺人、专辑点击时先收回侧栏再在内容区打开对应页面（全屏态下内容区被盖住）；卡片按现有规则依次出现（前一张未出结论时后面的不显示）。

### 4.3 侧栏 ⇄ 全屏过渡

侧栏态和全屏态是两套排版，铺开过程中不能逐帧重排。方案：

1. 进入全屏：卡片左边缘向左铺满（320ms，现状）的同时，侧栏排版淡出、全屏排版在铺开到约 60% 时开始淡入，两者都按各自的最终宽度排版一次，只做透明度过渡。
2. 退出全屏：反向，先淡入侧栏排版，再收回宽度。
3. 竖屏全屏与侧栏同为单列，只是宽度不同：铺开过程中内容列保持侧栏宽度居中，铺开到位的那一帧取消限宽铺满卡片，配一次轻微淡入盖住重排；退出时反向。（同一个列表不能同时按两种宽度存在，所以不做两份交叉淡入淡出。）
4. 横屏全屏态的右栏滚到顶后，多余的下拉量不再触发「下拉收起播放器」，避免往回翻歌词和卡片时误收起；收起用顶部下拉箭头。竖屏全屏沿用手机的下拉收起。

## 5. 实现结构

- `FullPlayerScreen` 目前把状态收集、各类弹层（队列、评论、更多、定时、输出设备、下载音质、收藏）和竖排列表写在一起。拆成两层：
  - **宿主**：状态、弹层、返回键处理，保持一份，侧栏 / 全屏 / 手机共用。
  - **排版**：现有竖排列表（侧栏、手机）和新增的全屏两栏排版，由宿主按场景选择。
- 新增 `FullPlayerWideLayout.kt`：全屏两栏排版，复用 `FullPlayerCoverArt` 中的封面、`SongInfo`、`ProgressSection`、控件行、快捷操作行、`FullScreenLyricsList` 与各信息卡片组件，不新造同类组件。
- 横竖屏由整屏方向判定（`rememberMelodiaOrientationClass`），与内容区断点无关。
- 手机端与侧栏态的现有行为不变，作为回归基线。

## 6. 风险

1. **宿主 / 排版拆分**：`FullPlayerScreen` 较大，拆分时需逐项核对弹层与返回键优先级，避免行为回退，是本次工作量最大、风险最高的一步。
2. **手势分流**：按下时需要知道每一行歌词文字的实际范围，需要在歌词行上记录文字边界，并在外层按下事件里判定，需真机调手感。
3. **两套排版同时存在的过渡期**：切换动画期间两套排版同时组合，首次进入全屏可能有一帧卡顿，需真机观察。

## 7. 不在本次范围

- 手机端全屏播放器、侧栏态排版的任何改动。
- 全屏态下的沉浸式全屏歌词页（`FullScreenLyricsView`）的改版；全屏态右栏已承担看歌词的需求，入口暂时保留原样。
